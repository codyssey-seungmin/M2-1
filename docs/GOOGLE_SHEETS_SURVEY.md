# 새 앱 평가를 내 구글 시트에 저장하기

**AI 코치 화면**의 🤗 앱 평가 버튼이 평가 페이지를 엽니다. 참여 코드는 직접 입력하지 않습니다. 첫 제출 때 U01, U02처럼 자동 발급되고 같은 브라우저의 재평가에는 같은 코드가 사용됩니다. 세 항목의 1~5점, 필수 개선 의견, 저장 동의가 필요합니다. 일기 원문과 AI API 키는 평가 데이터에 포함하지 않습니다. 기존 `/api/feedback`의 SQLite 설문과는 별개입니다. 코드는 **가명 식별값**이며 이름과 이메일은 시트에 기록하지 마세요.

같은 사람이라도 휴대폰과 노트북은 서로 다른 코드로 집계됩니다. 브라우저의 사이트 데이터를 지우면 새 코드가 발급됩니다. 앱의 **'이 브라우저의 모든 일기 기록 삭제'**는 참여 코드나 구글 시트의 평가를 삭제하지 않습니다.

구글 시트 연결 전에도 평가 페이지는 볼 수 있습니다. 다만 **제출은 저장되지 않으며**, 화면에 연결이 준비되지 않았다는 안내가 나옵니다.

## 한 번만 준비하기

1. 본인 구글 계정에서 **새 구글 시트**를 만듭니다. 시트 이름은 자유롭게 정해도 됩니다.
2. 시트 상단의 **확장 프로그램 → Apps Script**를 엽니다.
3. 열린 코드 편집기의 내용을 지우고 [google_sheets_receiver.gs](google_sheets_receiver.gs)의 코드를 전부 붙여 넣어 저장합니다. 파일 첫 줄의 `@OnlyCurrentDoc` 주석도 포함해야 합니다. 이 코드는 연결된 시트 안에 `앱 평가` 탭을 자동으로 만듭니다. 시트에는 제출 시각, 세 점수, 개선 의견, 자동 발급 참여 코드, 중복 방지용 제출 ID 순서로 A~G열이 생깁니다.
4. 오른쪽 위의 **배포 → 새 배포 → 유형 선택(톱니바퀴) → 웹 앱**을 선택합니다.
5. **실행 사용자: 나**, **액세스 권한: 모든 사용자(Anyone)**로 선택하고 배포합니다. 구글 계정 권한 확인 화면이 나오면 본인이 만든 스크립트인지 확인하고 승인합니다.
6. 표시된 **웹 앱 URL**을 복사합니다. URL은 `https://script.google.com/macros/s/…/exec` 형태여야 합니다. 이 주소를 GitHub 파일에 넣거나 공개하지 마세요.

권한 확인 화면에서 **모든 구글 시트에 접근**한다고 나오면 허용하지 말고 스크립트 맨 앞에 `@OnlyCurrentDoc` 주석이 있는지 확인하세요. 이미 배포했다면 코드를 저장한 다음 **배포 → 배포 관리 → 해당 배포 편집 → 새 버전 → 배포**로 최신 코드를 적용해야 합니다.

## 내 PC에 연결하기

VS Code에서 PowerShell을 열고 아래 한 줄의 `여기에_웹_앱_URL`만 본인의 URL로 바꿔 실행합니다. 이 명령은 Windows 사용자 환경변수에 주소를 저장하므로 매번 다시 입력할 필요가 없습니다.

```powershell
[Environment]::SetEnvironmentVariable('MINDILY_SURVEY_WEBHOOK_URL', '여기에_웹_앱_URL', 'User')
```

그다음 **VS Code를 완전히 닫았다가 다시 열고**, 새 터미널에서 앱을 실행합니다. 이미 실행 중인 Uvicorn도 종료 후 다시 시작해야 새 환경변수를 읽습니다.

```powershell
cd "$env:USERPROFILE\Desktop\M2-1"
.\.venv\Scripts\Activate.ps1
python -m uvicorn server:app --reload
```

브라우저에서 `http://127.0.0.1:8000`을 열고 **AI 코치 화면**의 🤗 앱 평가 버튼을 누릅니다. 세 점수와 개인 정보가 없는 시험 의견을 입력한 뒤 동의하고 제출합니다. 성공 안내에 참여 코드가 표시되면 구글 시트의 `앱 평가` 탭 F열에도 같은 코드가 있는지 확인합니다. 같은 브라우저에서 한 번 더 제출하면 같은 코드로 기록되어야 합니다. 시험 응답은 실제 사용자 응답과 구분해 두세요.

## 자동 참여 코드 기능을 기존 시트에 적용하기

이미 웹 앱을 배포했다면 Apps Script의 `Code.gs` 내용을 [google_sheets_receiver.gs](google_sheets_receiver.gs)의 **최신 코드 전체**로 교체해 저장하세요. `@OnlyCurrentDoc` 주석도 함께 복사해야 합니다. **배포 → 배포 관리 → 기존 웹 앱 편집 → 새 버전 → 배포**로 기존 배포를 갱신합니다. 웹 앱 URL과 Windows 환경변수는 다시 만들거나 입력할 필요가 없습니다.

기존 `앱 평가` 탭의 응답과 코드는 그대로 유지됩니다. 새 코드는 기존 F열에서 가장 큰 번호 다음부터 발급됩니다. G열의 제출 ID는 동일한 요청이 재전송돼도 행을 한 번만 추가하기 위한 값이며 이름이나 이메일이 아닙니다. 이전에 수동으로 부여한 코드와 새 브라우저 식별값은 자동으로 연결되지 않으므로, 이전 참여자가 새 방식으로 처음 평가하면 새 코드를 받습니다. 한 번 발급한 번호는 응답 행을 지워도 다시 사용하지 않도록 Apps Script 속성에 기억합니다. Apps Script 프로젝트 전체를 새로 만들면 이 발급 기록은 함께 옮겨지지 않습니다.

배포 중인 옐로우머그 허깅페이스 앱은 이 로컬 설정이나 GitHub 수정만으로 바뀌지 않습니다. 나중에 해당 Space를 배포한다면 소유자가 같은 웹 앱 URL을 허깅페이스 **Secret** `MINDILY_SURVEY_WEBHOOK_URL`로 별도 설정해야 합니다.
