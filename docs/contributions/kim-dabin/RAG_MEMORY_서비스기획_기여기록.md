# Mindily RAG·Long-term Memory 활용 서비스 기획 기여 기록

## 문서 정보

- 기여자: 김다빈
- 담당 영역: 서비스 문제 정의, 목표 사용자 설정, AI 활용 방식 및 개인화 흐름 기획
- 문서 성격: 개발팀에 전달한 기획 단계의 AI 서비스 구조 제안
- 정리 기준일: 2026-10-23

이 문서는 김다빈의 기획 기여를 기록합니다. 특정 라이브러리나 기술이 최종 앱에 모두 구현되었다는 의미가 아니며, 실제 구현 여부와 검증 결과는 저장소의 최종 코드·기능명세·결과보고서를 기준으로 합니다.

## 1. 문제 정의

김다빈은 기존 감정 기록 서비스에서 다음과 같은 문제를 정의했습니다.

- 감정을 기록한 뒤 사용자가 바로 실행할 수 있는 다음 행동이 부족함
- 일반적인 위로 문장만 반복되면 개인화된 도움으로 느끼기 어려움
- 추천 활동이 사용자의 이전 선호나 반응과 연결되지 않으면 반복 사용 가치가 낮아짐
- 감정 분석 결과뿐 아니라 짧고 구체적인 회복 활동까지 이어지는 흐름이 필요함

이를 바탕으로 `감정 기록 → 근거가 있는 활동 추천 → 짧은 활동 실행 → 선호 반영`으로 이어지는 서비스 방향을 제안했습니다.

## 2. 목표 사용자 기획

초기 핵심 대상으로 취업준비생과 초급 직장인을 제안했습니다.

| 대상 | 기획 단계에서 정의한 필요 |
|---|---|
| 취업준비생 | 반복되는 결과와 불확실성 속에서 감정을 짧게 정리하고 실행 가능한 활동을 선택할 필요 |
| 초급 직장인 | 업무와 인간관계에서 생긴 피로를 짧은 시간 안에 돌아보고 부담이 적은 활동으로 전환할 필요 |

이 대상 정의는 초기 기획 제안입니다. 실제 사용자 구성과 테스트 결과는 익명 참여 코드 기반의 사용자 테스트 문서에서 별도로 확인합니다.

## 3. AI 활용 흐름 제안

김다빈이 기획 단계에서 제안한 흐름은 다음과 같습니다.

```text
사용자 감정 기록
→ 이전에 저장한 활동 선호 확인
→ 감정·스트레스·선호에 맞는 근거 자료 검색
→ 검색 자료를 바탕으로 코치 문장과 짧은 활동 제안
→ 사용자가 활동을 선택
→ 동의한 선호 정보를 다음 추천에 반영
```

이 흐름은 RAG와 Long-term Memory를 각각 독립된 부가 기능으로 두지 않고, 한 번의 개인화 추천 과정에서 함께 활용한다는 기획 방향을 담고 있습니다.

## 4. RAG 활용 기획

RAG는 생성형 AI가 임의의 활동이나 효과를 만들어내는 것을 줄이고, 확인 가능한 자료를 바탕으로 추천하도록 하기 위해 제안했습니다.

기획 단계의 요구사항은 다음과 같습니다.

- 공신력 있는 기관의 호흡·감각 활동·걷기 등 회복 활동 자료를 사용
- 자료를 검색 가능한 단위로 정리
- 감정, 스트레스, 사용 가능 시간과 관련된 자료를 검색
- 관련도가 높은 자료를 생성형 AI의 입력 근거로 사용
- 사용자가 추천 근거의 제목과 출처 URL을 확인할 수 있도록 표시

초기 원자료에서는 LangChain, LlamaIndex, ChromaDB, Pinecone 등을 적용 후보로 검토했습니다. 이는 기획 단계의 후보 기술이며 실제 채택 또는 구현을 주장하는 내용이 아닙니다.

## 5. Long-term Memory 활용 기획

Long-term Memory는 사용자가 동의한 개인화 정보만 보관하고 다음 추천에 활용하는 방향으로 제안했습니다.

기획 단계에서 검토한 정보는 다음과 같습니다.

- 사용자가 선호하는 활동 종류
- 이전에 선택한 회복 활동
- 추천 결과에 대한 사용자 반응

감정 일기 원문과 민감한 개인 정보는 장기 기억 대상으로 사용하지 않는 것을 원칙으로 제안했습니다. 저장 항목, 보관 기간과 삭제 방법은 실제 구현 단계에서 개인정보 최소 수집 원칙에 맞춰 확정하도록 했습니다.

## 6. 짧은 회복 활동 기획

사용자가 긴 활동을 부담스러워하지 않도록 짧고 구체적인 활동을 제안하는 방향을 설계했습니다.

- 호흡과 감각 돌아보기
- 짧은 걷기 또는 스트레칭
- 생각을 정리하는 간단한 기록
- 자연의 소리 또는 차분한 음악 듣기
- 주변 환경을 가볍게 정돈하는 활동

초기 기획에서는 3분 활동을 중심으로 검토했으며, 최종 시간과 활동 구성은 개발 과정의 검증과 사용자 피드백에 따라 조정하는 것으로 정리했습니다.

## 7. 기획 제안과 실제 구현의 구분

| 항목 | 이 문서에서 증명하는 내용 | 증명하지 않는 내용 |
|---|---|---|
| RAG | 외부 근거를 검색해 생성 응답에 활용하는 서비스 방향을 제안함 | 특정 Vector DB 또는 라이브러리의 구현 완료 |
| Long-term Memory | 동의한 선호를 다음 추천에 반영하는 개인화 흐름을 제안함 | 감정 이력·스트레스 원인의 장기 저장 완료 |
| 마이크로 활동 | 짧고 실행 가능한 회복 활동의 필요성과 유형을 제안함 | 모든 제안 활동의 최종 구현 완료 |
| 목표 사용자 | 취업준비생과 초급 직장인을 초기 핵심 대상으로 제안함 | 실제 테스트 참여자의 직업을 추정하거나 임의로 분류함 |

## 8. 개발팀 전달 요구사항

기획 단계에서 개발팀에 전달할 핵심 요구사항은 다음과 같습니다.

1. 추천 문장에는 확인할 수 있는 출처를 표시합니다.
2. 사용자가 동의한 선호 정보만 개인화에 사용합니다.
3. 저장된 선호를 삭제할 수 있는 기능을 제공합니다.
4. 감정 기록을 의료 진단이나 치료 결과처럼 표현하지 않습니다.
5. AI가 생성한 문장과 규칙 기반 문장을 구분해 안내합니다.
6. 구현하지 않은 기술과 기능을 완료된 것으로 문서화하지 않습니다.

## 9. 기여 요약

이 문서는 김다빈의 다음 기여를 증명합니다.

- 감정 기록 이후 행동이 부족하다는 문제 정의
- 취업준비생과 초급 직장인을 중심으로 한 목표 사용자 제안
- RAG와 Long-term Memory를 결합한 개인화 추천 흐름 기획
- 짧고 실행 가능한 회복 활동의 서비스 콘셉트 제안
- 개인정보 최소 수집과 출처 표시 요구사항 제안

실제 기술 보완, 코드 구현과 배포 검증은 개발 담당 산출물에서 별도로 기록합니다.
